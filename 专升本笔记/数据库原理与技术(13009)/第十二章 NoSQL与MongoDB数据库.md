传统关系数据库的不足
	大数据环境下I/O较高
	维护索引的成本高
	维护数据的一致性的代价大
	表结构模式扩展不方便
	全文搜索功能较弱
	存储和处理关系型数据的功能较弱
NoSQL的含义及其由来
	NoSQL 数据库的产生是为了 解决大规模数据集、多重数据种类带来的挑战，尤其是大数据应用难题。例如：
		对数据高并发读/写的需求
		对海量数据的高效率存储和访问的需求
		对数据库的高可扩展性和高可用性的需求
NoSQL数据库存在的三大基石:
	最终一致性:分布式一致性规则
	CAP,又称布鲁尔定理，对一个分布式系统来说,不可能同时满足以下三点：
		一致性:所有节点在同一时间具有相同的数据
		可用性:保证每个请求不管成功或者失败都具有响应
		分隔容忍:分布式系统中存在网络分区的情况下，任意信息的丢失和失败不会影响系统的继续运行
	BASE,对CAP中一致性和可用性权衡的结果
		核心思想:即使无法做到强一致性,但每个应用可以根据自身业务特点,来用适当的方式使系统达到最终一致性
		BASE理论的三要素:
			Basically Available (基本可用)
			Soft State (软状态)
			Eventually Consistent (最终一致性)
NoSQL的优缺点:
	优点:
		高可拓展性
		分布式计算
		低成本
		架构的灵活性,半结构化数据
		没有复杂的关系
	缺点:
		没有标准化
		有限的查询功能
		最终一致是不客观的
NoSQL数据分类:
	键值存储
		以键值对形式存储和查询数据
		特点：
			模型简单
			易于实现
			读/写效率高
		缺点:
			不支持条件查询
		典型代表:
			Redis
	文档存储
		以文档的形式存储和查询数据
			通常以标准的JSON格式或者XML格式数据存储数据
		典型代表:
			MongoDB
			CouchDB
	列式存储
		围绕“列” (Cloum) 而不是接关系数据库围 绕“行” (Row) 来存储数据。这样，属于同一列的数据会尽可能地存储在磁盘的同一个页 (Page ) 中，而不是将属于同一行的数据存放在一起。其特点是当要查询海量教据时，由于每次涉及的 列不会很多，可以大大节省读/写磁盘的时间。
		列是列族数据库的基本存储单元，如果列数较多，可以把相关的列分成组，称为“列族”
		典型代表:
			Big Table
			Cassandra
			Hbase
	图式存储
		以节点和关系 (即顶点和边) 来存储数据
			节点 (Node) 是具有标识符和 一系列属性的对象
			关系 (Relationship) 是两个节点之间的链接，它是有权重的有向边，可以 表示节点之间的联系。
		典型代表:
			Neo4j

云计算
	是一种按使用量付费的模式,这种模式提供可用的,便捷的,按需的网络访问
	按照服务的形式,目前云计算分为三种:
		Iaas(基础实施及服务)
			消费者通过Internet从完善的计算机基础设施获得服务,如网上租用服务器
		Paas(平台即服务)
			指将软件研发的平台作为一种服务,以SaaS的方式提供给用户使用
		SaaS(软件即服务)
			用户无需一次购买昂贵的软件,通过网络租用供应商的软件即可
MongoDB的概念
	由C++语言编写的，一个基于分布式文件存储的、可扩展的、开源的、面向文档的數 据库系统
	特点:
		模式自由
			可以把不同结构的文档存储在同一个数据库里
		面向集合的存储
		完整的索引支持:对任何属性可索引
		复制和高可用性
			支持服务器之间的数据复制,支持主/从模式及服务器之间的相互复制,复制的主要目的是提供冗余和自动故障转移
		自动分片
			支持云级别的伸缩性,自动分片功能支持水平的数据库集群,可动态添加额外的机器
		丰富的查询
			支持丰富的查询表达方式,查询指令使用JSON形式的标记,可轻易查询文档中内嵌的对象及数组
		快速就地更新
		高效的传统存储方式:支持二进制数据及大型对象
